## 1. 점수 구조 — 이게 모든 판단의 기준

Brier Skill Score `= 1e5 · (1 − Brier / [ȳ(1−ȳ)])` 이고, 다음처럼 분해된다.

```
S = 2C − W − B          C = K·Cov(p,y)   W = K·Var(p)   B = K·bias²   K = 1e5/V
refine = C²/W = 1e5·ρ²  ← 최적 아핀 재보정 후의 점수 = 그 예측이 가진 정보량
S = refine − (기울기 손실) − (절편 손실)
```

**refine 과 캘리브레이션 손실은 독립적으로 움직인다.** 이걸 섞으면 판단이 망가진다
(`probeA` 는 `seed_ensemble` 을 +0.03 옮긴 것이라 정보량은 같은데 점수는 868.76).

### 2025 실측 상수 (리더보드 프로브로 역산, 확정)

```
ȳ(2025) = 0.46088     V = 0.24847     K = 402463
dual20:  W = 1192.2   C = 1163.9   β = 0.976   ρ = 0.10662   refine = 1136.9
1200 에 필요한 ρ = 0.10954   (현재 대비 +2.74%)
```

**dual20 은 아핀 보정이 이미 끝나 있다.** 상한 1136.9 에 실측 1135.55, 손실 0.67.
이동·수축·확장으로 얻을 게 없다. 남은 건 전부 ρ 다.

## 2. 검증 프로토콜 — 반드시 이대로 할 것

지난 30여 회의 실패는 대부분 검증이 느슨해서 생긴 착시였다. 아래를 지키지 않은 결과는 믿지 말 것.

1. **전방(forward)**: 대상 시즌은 학습·테이블 생성에서 완전히 제외. `evaluation/dual20_forward_full.npz`
   에 2022/2023/2024 의 forward 예측(`y22`/`p22` …)이 들어 있다.
2. **시즌 하나씩 빼기(leave-one-season-out)**: 대상 t 의 테이블은 나머지 두 시즌에서만.
3. **시즌별 평균 제거**: 잔차를 모으기 전에 각 시즌의 평균 잔차를 뺀다. 그 해의 전역 레벨은
   다음 해로 **전이되지 않으며**, 그대로 두면 그 위에 얹힌 구조를 통째로 덮어버린다.
4. **판정은 실제 점수 변화**로. `refine_r` 만 보면 상수 성분 때문에 부호가 뒤집힌다
   (실제로 `refine_r +52.80` 인데 점수는 −23.16 인 사례가 있었다).
5. **선택 자체를 검증**: 후보를 여럿 놓고 고를 때는 두 시즌으로 고르고 나머지 한 시즌에서 확인.
   479개 후보에서 8개를 고른 확장이 홀드아웃 +8.30 으로, 고르지 않은 6채널 +10.30 보다 낮았다.
6. **2023 은 이상 시즌**: dual20 의 β 가 2022=1.0375, 2024=1.0429, **2025=0.976** 인데
   2023 만 0.3353. 2023 단독 결과에 끌려다니지 말 것. 다만 게이트에서 빼지도 말 것.

도구: `research/sweep_centered.py`, `research/greedy_channels.py`,
`research/validate_extension.py`, `research/screen_channel.py`

### (B) 아핀 블렌드 — 신뢰도 중간, +11 ~ +26

채점된 제출 22개의 아핀 조합. **항등식이라 추정이 아니다.**

```
S(Σwᵢpᵢ) = Σwᵢ·Sᵢ + ½ΣΣwᵢwⱼ·Gᵢⱼ        (Σwᵢ = 1)
Cᵢ = (Sᵢ + Wᵢ + Bᵢ)/2                  ← Sᵢ 는 리더보드 실측이라 정확
refine(w) = (C'w)² / (w'Σw)
```

Σ 만 추정 대상이고, 그 정확도는 두 지점에서 실측돼 있다.

```
대각 W:   shifted 로컬 1031.5 대 사이트 1027.54  →  0.4% (아주 좋음)
비대각 G: blend50 이 G(gate,split)=48.83 을 고정. 로컬 66.35 → c = 0.736
          (로컬은 모델 간 불일치를 36% 과대추정. 2023/2024 프레임끼리는 서로
           일치하므로 이 편의는 시즌 간 비교로는 절대 안 잡힌다)
```

`hull3` 의 w: `|w|₁ = 9.71`, λ = 1.166, 항등식 1173.5 (c=0.736).
예측 이득 +36.6 에 실현율 0.30~0.70 을 곱해 **+11 ~ +26**.

실현율 근거: 정답 있는 프레임에서 절차 전체를 리허설(`research/selection_bias.py`).
사이트 실측은 `blend50` 하나뿐이고 그건 0.856 이었다(단 `|w|₁=1`, 전부 양수 가중치).

## 7. 반드시 지킬 것 (오늘 사고 두 건)

**(1) 제출 실패 — `ModuleNotFoundError: No module named 'catboost'`**
래퍼가 멤버를 `subprocess` 로 띄우며 cwd 를 옮겼는데 채점 환경의 새 파이썬이 catboost 를
못 찾았다. → `runpy` 로 **같은 인터프리터 안에서** 실행하도록 교체. 무거운 의존성은
cwd 를 바꾸기 **전에** 미리 import 해두어 멤버의 import 가 캐시 조회가 되게 한다.
멤버들이 각자 `src/` 를 갖고 있고 `src/preprocessing_v2.py` 가 **5가지 다른 버전**이므로,
멤버 실행 후 `members/` 아래에서 온 모듈을 `__file__` 과 `__path__` 양쪽으로 훑어 제거해야
한다. 안 하면 오류 없이 조용히 틀린 값이 나온다.

**제출 전 반드시**: 의존성이 깔리지 않은 환경에서 실제로 한 번 돌려볼 것.

**(2) 멤버 zip 유실**
정리 중 `F_regime075`, `JM_R075`, `JY_R015` 등이 사라져 빌드가 깨졌다. → `member_zips/` 에
쓰기 금지로 보관하고 빌더가 거기서만 읽도록 고정했다. **`member_zips/` 는 건드리지 말 것.**

**빌드 후 항상**: 항목 수(hull 계열 988개)와 `unzip -t` 확인.
경합으로 파일이 빠진 채 압축되면 구조는 멀쩡해 보이는데 내용이 불완전하다(909개 사례 있음).
